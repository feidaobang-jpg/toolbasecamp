# v0.1.1 开发笔记：三处镜头问题（2026-10-05）

## 起因

做 B 站「侧视 / 正视 / 第一人称」视角版视频时，用 record_views.cjs + qa/bot.js 录了同一局实机（穆斯塔法，seed 7），回看发现三处镜头问题：

1. 正视在第 47 街贴着后墙时，bot 按 Q/E 转头找身后的敌人，镜头整个钻进砖墙，满屏砖纹（录像约 176.8 s、180.4–181.8 s）。
2. 第一人称跟岩跳龙贴身，画面变黑或露出牙齿和模型内部（约 223.8–224.8 s）。
3. 侧视 Boss 战尾段，维斯被打到画面右缘外面（约 279–283 s、290 s）。原作锁屏不出画。

## 查到的原因

- 大楼内部的墙早就有「镜头到墙外就整层剖切」，第 47 街的后墙没有登记剖切，也没有任何机位避让。正视镜头绕主角约 7.4 米转圈，转到墙那一侧就落在墙后。
- 第一人称眼睛就放在主角头部中心，角色之间的分离距离只有 0.56～0.71 米，贴身时模型直接穿过近裁剪面。黑屏来自描边：描边是把模型往外扩一圈的背面外壳，镜头进到外壳里，看到的全是黑色背面。
- 锁屏只限制了主角，敌人允许走到焦点 ±(HALF_W+2.2)，被打飞时自然出画。顺带量出来：侧视取景只保证观察点那一排看到 ±(HALF_W+0.9)，透视下最前一排画面更窄，主角站最前排贴边时自己也会被切掉一块。
- 意外发现：户外的「遮挡主角时半透明」从来没生效过。three.js 不透明材质编译时带 OPAQUE 宏，片元 alpha 固定为 1，运行中只改 transparent 标志不会重编着色器。

## 取舍

- 后墙紧贴走道（最里排离墙面只有 0.8 米），靠把镜头拉近躲不开——拉到能躲的位置，主角会塞满画面。按 game-maker「正视与第一人称」的做法分两层：贴着走道的整面墙（后墙、起点楼体立面）用剖切，镜头到墙后就整层隐藏；墙后的瓦砾堆、远处废墟这类零散实体才做避让，正视先抬高 1～2 米，抬不开再沿视线拉近。剖切后又发现镜头在墙前 0.4 米、贴着墙面平视时，侧面大片砖墙占三分之一画面，于是加了「贴近 0.6～0.7 米内整面墙渐隐」。阈值卡在主角站最里排时墙离镜头的距离以内，正常正视和第一人称不会把旁边的墙变透明。
- 第一人称三选一（推开身位 / 按距离淡化 / 调近裁剪面）：近裁剪面已经是 0.06，再小也挡不住模型整个穿过镜头；推开身位会改变打击手感。选了按距离淡化：算镜头到对方每个部件包围球的最近距离，0.5 米起渐隐，最低 15% 不透明，同时藏掉描边外壳和手持武器。
- 淡化第一次触发时现编着色器，实测卡 55 ms。开局用临时代理网格把透明变体预编译好，首次淡化降到 2.5 ms。
- 锁屏：敌人、Boss、被打飞或被抓的角色和主角共用一个窗口 ±(HALF_W-0.7)；岩跳龙连尾巴三米多，再多留 1.45 米；倒地横躺的身体比站着多占半个身长，贴边倒下时再往里滑 0.45 米（滑进来，不瞬移）。侧视取景改成按最前一排纵深保证这个窗口完整入画，16:9 下镜头约拉远 8%，人物略小一点。

## 验证

新写 qa/camera.js，用射线取样（离镜头 0.9 米内的实心面占比）、读像素（暗像素占比）、逐顶点投影（出画量）把三处问题量化，同一个脚本对旧构建也能跑：

| 项目 | 旧构建 | 新构建 |
| --- | --- | --- |
| 正视在第 47 街 5 个站位各转一整圈，满屏近物最大值 | 0.556，主角被挡 8 次以上 | 0，主角始终可见 |
| 第一人称维斯贴到 0.05 米，暗像素 | 100%（整屏黑） | 0% |
| 侧视 Boss 战 bot 实打 40 秒，最大出画量（NDC） | +0.361（16:9）/ +0.336（2.17:1） | ≤ -0.008，全部在画内 |
| 汇总 | 4/11 | 11/11（本地与线上各一次） |

desktop 88/88、mobile 34/34；测帧各段 170 FPS 上限、无长帧。中途 qa/camera.js 自己也踩了两个坑：射线检测碰到 Sprite 要给 raycaster 设 camera；主角受击无敌闪烁正好落在隐藏帧时投影为空，测试前先清无敌。
