# v0.1.0 开发笔记（真实经历）

## 本次目标
把 FC《魂斗罗》第一关做成 3D 网页 demo：保留"跑、打、跳"的核心循环，把丛林、桥、河、堡垒墙四个标志性场景翻译成 3D，并按站内统一规范做双端适配。

## 技术路线
- 沿用 mario-3d 已验证的工程结构：`world.js` 确定性玩法 / `scene.js` 渲染 / `main.js` 输入编排 / `audio.js` 振荡器音效，Three.js 0.170.0 走仓库 vendor 同源加载。
- 玩法层刻意做成纯函数式可单测：`world.js` 不 import THREE，所以在 Node 里就能跑完整逻辑断言（6 项全过）。这在写渲染前就抓住了桥连锁计时的边界。
- 桥的连锁爆炸做成"踩到→0.55s→爆→相邻段 0.38s 引信"，逼玩家不停奔跑；水域做减速+潜水两档状态，潜水时无敌但哑火——复刻原作"下水只能露头打"的取舍。

## 真实问题与处理
1. **音频 NaN 崩溃（QA 抓到的第一个真 Bug）**：`die` 音效把频率数组整个传给了 `tone()`，Web Audio 的 `setValueAtTime` 收到 NaN 直接抛 TypeError，且只在玩家死亡时触发——无头 QA 跑移动采样时玩家正好被冲锋兵撞死才暴露。逐个排查后改成 `forEach` 逐音符调度，重跑三场景零报错。
2. **棕榈树穿模**：首版截图目检发现树干摆在 z=±2.4，在玩家可玩区（|z|≤2.55）内。装饰摆放没对照玩法 clamp 范围。移到 |z|≥3.05 后重拍确认。
3. **Edge 无头第二次进场景必崩**：Playwright 里同一浏览器进程关掉首个 WebGL context 后再开新页会 TargetClosedError，换全新浏览器实例也一样。最后把 QA 脚本改成单场景单进程绕过。录像也踩坑：`recordVideo` 与 WebGL 组合直接崩，最终用 CDP screencast 截流 + 仓库精简版 ffmpeg（只有 mjpeg 解码 + vp8 编码，还得把帧拼成单文件走 image2pipe）合成 webm。
4. **瞬移截图被炮台秒杀**：QA 用瞬移 Shortcut 拍水域时，玩家落到炮台枪口下 0.9 秒内就阵亡回检查点，拍到的是出生点。给瞬移加 6 秒无敌后各场景拍全。

## 取舍
- 一击死对网页玩家偏硬，但这是魂斗罗的身份；用 3 条命 + 检查点 + 复活无敌缓冲，不做血条。
- 不做鼠标瞄准/自动锁定，射击方向绑定角色朝向，深度轴的敌人靠走位对线——保持"跑打"的操作质感。
- Boss 简化为堡垒墙双炮（各 4 血），没做门内刷兵，留作 v0.2 空间。
