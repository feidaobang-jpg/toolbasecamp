# v0.1.0 开发笔记（真实经历）

## 本次目标
用户在坦克大战 3D 之后说：「你也做一个网页游戏 FC 超级玛丽 3D 版的第一关吧，我拿去对比一下哪边效果好」。仓库里已有另一个模型做的 mario-3d。

## 关键决定：做原创同类作品
超级玛丽的角色、敌人和 1-1 关卡受版权保护，不能复刻。向用户说明后提出替代方案：原创主角、敌人、道具和关卡，保留经典横版闯关的手感，用 3D 立体布景比较画面与技术效果；用户选择「原创横版闯关（推荐）」，并要求先不加进游戏中心。于是有了橙色小狐狸「跳跳狐」、甲虫、蜗牛、木箱、陶砖、发光莓、萤火灯笼、弹跳叶片、移动浮木，终点是铃铛旗杆和磨坊小屋。

## 和现有 mario-3d 的差异（给对比视频用）
- mario-3d 是可以前后自由走的 3D 跑道；这版保持横版闯关的平面操作，把 3D 用在布景、镜头和角色动画上：小路架在河岸上，前面是流动的河，后面是低多边形树林、远山和云，Q/E 转过去能看到整条路线沿河蜿蜒。
- 手感参数单独做过：可变跳跃高度（点按约 1.7 格、按住约 3.4 格、奔跑起跳约 4.7 格）、土狼时间、跳跃缓冲、顶角修正、急转身刹车。

## 技术路线
- 沿用坦克大战 3D 的结构：`world.js` 纯逻辑（Node 可跑）、`scene.js` 渲染、`main.js` 输入与流程、`audio.js` 原创配乐与音效。
- 先写 13 项 Node 断言（速度、跳跃高度、墙、顶箱、道具、踩踏、蜗牛壳、坑与检查点、弹跳叶、浮木、终点结算、脚本玩家通关），再写画面。

## 真实问题与处理
1. **走路速度到不了上限（Node 断言抓到）**：到达最高速后进入「超速减速」分支，把速度拉到 5.87 而不是 6。改成只在超过上限时才减到上限。
2. **弹跳叶片弹不高（断言抓到）**：松开跳跃键就用大重力下落，叶片弹射只有 4.3 格。弹射后在上升阶段固定用小重力（boost 标记），峰值约 9.7 格。
3. **终点烟花无限循环（断言抓到）**：烟花计数减到 0 又被当成「还没开始」重新设为 3，结算永远不结束。加 fwStarted 标记。
4. **第一次截图卡住 30 秒**：背景 90 棵树的树冠用了 20×14 段球体，场景 5.4 万三角形，软件渲染每帧要好几秒。树冠换成低多边形二十面体（也更有画风），山丘降段数。
5. **路两边是空的**：第一版小路像悬在空中的长条，坑里和旋转视角都能看到浅色虚空（assets/dev-stages/02、03）。加了河流（坑直接落进河里）、后方草地台和远岸（04 为修改后）。
6. **云像灰色石头**：平面着色 + 场景光让云发灰，改成柔和的 Lambert 自发光白云，放得更高更远。
7. **风车叶片穿过屋顶、烟花在画面外**（assets/dev-stages/05）：叶片移到侧塔上并缩小；烟花高度从 9–11 格降到 6–8 格。
8. **30 fps 下踩敌人会判成撞上（真 Bug，脚本玩家暴露）**：同一个脚本玩家在 60 fps 模拟里能通关，按采集时的 30 fps 时序重放却总死在甲虫身上。追踪发现下落速度到 -22 格/秒时，一帧会移动约 0.7 格，踩踏判定用的是移动后的脚底位置，直接越过了「从上方」的判定窗口，被当成侧面相撞。改为同时参考这一帧开始时的脚底位置。手机或低帧率电脑上玩家也会遇到同样问题，这次一并修掉。
9. **脚本玩家过不了移动浮木**：它带着奔跑速度一口气跳过台阶，在空中错过浮木掉进河里。给 QA 脚本加了状态：走上顶层台阶、等浮木回来、跳上去、到对岸端再跳下。这是测试工具的问题，不影响游戏本身。

## 取舍
- 保持横版平面操作而不是自由 3D 行走，优先保证跳跃手感与关卡可读性；镜头旋转限制在 ±55°，左右键始终对应屏幕方向。
- 装备系统没有「变大」，而是戴矿工帽 / 提萤火灯笼，和经典作品区分开。
- 未加入游戏中心，等对比结果。
