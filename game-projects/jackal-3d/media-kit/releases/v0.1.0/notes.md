# v0.1.0 开发记录

本次用户明确要求用 web-game-maker 制作 FC 赤色要塞第一关的 3D 重制版，按完整第一关 Demo 执行。

核心变化：把熟悉的吉普救人循环放进有体积、阴影与可辨识模型的低模三维前线。地图按营房、河桥、营区、直升机与四辆坦克连续展开。没有复制 ROM、原版美术或音乐。

## 真实问题与修复

1. 最初模型合批混用了索引几何体与非索引二十面体，Three.js mergeGeometries 报兼容错误，场景载入失败。统一为非索引几何后恢复。未捕获故障原片；保留错误描述，不重演冒充首次发生。
2. 连续死亡测试发现，倒计时减过零后留下约 -0.006；后续 `if(player.dead)` 把负数当作死亡状态，阻止正常受伤。复活赋值显式归零；已连续三次击毁复活，且验证保护结束后再次扣血。
3. 原先切换镜头会清空正在按住的摇杆与攻击，触屏需要重新按下。两种视角水平轴一致，取消不必要的清空；检查切镜头时移动与射击状态仍保留。
4. 直升机离场计时起初只在车停在接应点时推进，离开后直升机可能停在空中。改为独立推进离场计时，离场后隐藏；再次载员接应时返回。
5. 调整目标箭头的水平旋转符号；粒子死亡清理与实例矩阵写入分开，避免数组压缩时使用旧实例位置。

## 实机与迭代身份

`captures/iteration-01/` 与 `captures/iteration-02/` 是保留在本机的中间版本材料，不登记为最终构建证据。iteration-01 包含早期 8 人撤离录像，不能作为 9 人全救证据；iteration-02 对应指纹 d0f930efd0c6dece9698c04040e7908450aa0e0bc5145b1b18f7a3eb7656c199。最终媒体只使用 captures 顶层文件并绑定当前 build.json 指纹。

完整路线录像通过 Playwright 真正发送键盘输入，未传送、改伤害或启用无敌。功能回归中的定点死亡、河桥定位、性能营区定位是明确标识的测试设置，不能包装成人工正常游玩的结果。手机素材是桌面浏览器触摸模拟。
