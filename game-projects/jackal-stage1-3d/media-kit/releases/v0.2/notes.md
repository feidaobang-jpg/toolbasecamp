# v0.2 开发笔记（真实经过）

## 本次目标

v0.1 交付后，用户问：主角是保留「中一颗子弹就死」的经典模式，还是改成受击 3 次、血条，或者吃敌人掉落的补血道具？

我的建议是折中：默认 3 格护甲，受击后约 1.2 秒闪烁无敌；修理包不做随机掉落，固定放在营房里（每个营房炸开掉一个，全关 7 个），因为原作的乐趣核心本来就是炸营房；经过检查点自动补满；菜单加「耐久：标准 3 格 / 经典一发」，保留原作手感。用户回复「好」，于是按这个方案做成 v0.2。基线是 v0.1（构建 v0.1-7c08b3582259）。

## 取舍

- **为什么不用血条**：吉普中弹的反馈在 v0.1 里只有「爆炸 → 复活」一种，加长血条会让每颗子弹的分量变得很轻，也和 FC 的节奏不搭。3 格可以在 HUD 上一眼数清，和原作的「一发」也能用同一个界面切换。
- **为什么修理包固定在营房**：随机掉落要调掉率，还会让同一种子的录像结果不可复现。绑在营房上，玩家本来就会去炸，也能顺便提醒「营房里有好东西」。
- **护甲满时修理包留在原地**：不会白白浪费，之后受伤可以回来拿。
- **经典一发模式下的修理包**：改成 +300 分，这样两种模式的关卡内容一致。
- **炮弹也只扣 1 格**：第一版先保持规则简单，不区分子弹和炮弹。
- **阵亡惩罚不变**：护甲打光后和 v0.1 一样，武器回到手雷、俘虏散落；复活时护甲补满。

## 实现

- 玩法：`hitPlayer()` 统一处理受击：护甲 > 1 时扣 1 格，进入 1.2 秒无敌、车身闪白 0.22 秒、镜头轻震、播放受击音；否则走原来的 `killPlayer()`。检查点和复活时补满，检查点提示里会写「护甲已补满」。
- 画面：修理包是新做的程序化模型（黄色工具箱 + 扳手 + 绿色光圈），掉落时会弹一下；只剩 1 格护甲时车尾冒深色烟。
- 界面：主菜单新增「耐久」一项（保存到本地）；HUD 命数卡片下面加了护甲格，剩 1 格时变红闪烁，经典一发时显示金色 1 格并标「一发」；受击时画面四周闪红；结算里写上耐久模式、受击次数和修理包数。
- 声音：新增受击和修理两个合成音效。

## 遇到的问题与处理

1. **受击红边在逐帧录制里看不到**：第一版红边用 CSS 动画（0.45 秒），按真实时间播放。离线录制每帧要渲染约 1 秒，截图时动画早就结束了。改成由游戏时间驱动透明度（`G.hurtFx` 每个逻辑步衰减），实时游玩和逐帧录制看到的一样。
2. **受击闪白那一帧吉普消失了**：受击后的无敌闪烁把车身隐藏了一半的帧，正好和闪白冲突。改成闪白期间不闪烁。
3. **残甲的烟不够黑**：烟雾粒子会从起始色渐变到浅灰，第一版看起来还是白烟。给烟雾加了可选的终止色，残甲烟改为深灰到灰。
4. **测试钩子误删了隐藏星**：新的护甲检查要先清场，用了测试钩子 `kill()`，结果把隐藏星也当成实体删了，后面的「炸出隐藏星」检查失败。这只影响测试，不影响游戏；改成 `kill()` 默认跳过隐藏星。
5. **截图脚本**：第一次截受击画面时用 `kill()` 清场，分数被清场加到 16500，还弹出「坦克里关着一名闪光俘虏」的提示，画面不真实。改成不清场，在敌人旁边截图；修理包和检查点两张用短暂无敌防止被周围敌人打掉，截图前一帧关掉无敌，避免吉普正好闪烁消失。

## 结果

- 桌面纯键盘 80/80（v0.1 是 62 项，新增 18 项：耐久菜单、开局 3 格、营房掉包、满甲不捡、受击扣甲与无敌、HUD 同步与红边、无敌期不扣甲、残甲变红、红边消退、第 3 次才毁、复活补满、捡包 +1、检查点补满、经典一发 HUD / 修理包加分 / 一发毁、结算注明模式）。
- 手机模拟触控 33/33（新增：点「耐久」切换、横屏 HUD 护甲不压按钮、竖屏旋转后护甲卡片完整可见）。file:// 直接打开仍可运行。
- bot 对比（同一个笨 bot，手动时钟，非真人）：
  - 会躲子弹：标准 3 格在 seed 11 / 23 / 67 / 41 都 0 阵亡通关（v0.1 同样的 bot 在 11 / 23 / 67 阵亡 5 / 4 / 1 次）；受击 2～4 次。
  - 不躲子弹（模拟手生的玩家）：seed 11 标准模式阵亡 6 次、受击 19 次、208 秒通关；经典一发阵亡 28 次、386 秒通关。
  - 结论只能说：标准模式比原作宽松很多，经典一发保留了原作的压力。没有真人试玩，不能当作最终难度结论。
- 录像：seed 11 关闭躲子弹的 bot 录了 61 秒的护甲演示（offline-render，逐帧渲染约 33 分钟，含离线渲染音轨）：营房掉包、受击扣甲、捡修理包、炮弹受击、残甲黑烟、第 3 次被击毁、复活补满都在里面。这一局经过检查点时护甲正好是满的，所以录像里没有「检查点补满」，这一点由截图（测试钩子摆拍，已标注）和自动检查证明。录像局和空跑的同一种子结果不一样（录像多了菜单渲染和高画质参数），录像本身是真实的一局。CRF18 版 25 MB 超过写回上限，改用 CRF20（18.5 MB）。
- 截图：耐久菜单、营房掉包、受击闪红、残甲黑烟、修理包、捡包、检查点补满、经典一发菜单与 HUD、结算。受击截图里的敌弹是测试钩子放在吉普西侧 3 米处的（真实的判定和受击流程），handoff 里已标注。

## 待办 / 缺口

- 真人试玩和人工听审仍未做；新音效（受击、修理）只确认能触发、出现在离线音轨里。
- 性能没有重新测：本版只多了最多 7 个小修理包模型和 HUD 元素，没有理由认为帧率有明显变化，但没有新数据。
- 炮弹是否应该扣 2 格、修理包数量是否合适，都要等真人试玩后再定。
