# 横屏、全屏与统一操作

这些是用户对 game-maker 游戏的统一要求。所有玩法、菜单和结算均可用电脑键盘或手机触屏完成；不设计鼠标专属瞄准、拖拽、点选目标或 Pointer Lock 操作。

## 电脑键盘

| 输入 | 默认用途 |
| --- | --- |
| W/A/S/D | 上/左/下/右；3D 为相对水平视角的前进、左移、后退、右移 |
| J | A：主要动作/攻击（方阵下排左） |
| K | B：跳跃；无跳跃时为次要动作（方阵下排右） |
| U | C：第三动作（方阵上排左） |
| I | D：第四动作（方阵上排右） |
| L / O | 第 5、6 个动作：方阵右侧加一列，L 在下、O 在上（键盘 U I O / J K L 一一对应）；不为凑齐按键添加玩法 |
| Q/E | 按住无极左右旋转视角（所有游戏都有） |
| C | 循环切换视角预设并回正朝向 |
| Enter | 开始、确认、结算后重玩 |
| Esc | 暂停/返回；浏览器退出全屏优先，不拦截退出通道 |
| Tab、方向键、Enter | 菜单焦点、选择与确认；保留可见焦点 |

动作键位（用户 2026-10-05 确认）：按小霸王 / 街机手柄的 2×2 方阵分配——街机下排 A、B，上排 C、D，对应键盘 J K / U I（键盘上 U I 正好在 J K 上方，手感一一对应）。老游戏原先用 L 做第三动作的，迁移到 U / I 时保留 L 为别名。切换视角固定 C，不占动作键。

以动作映射共用键盘与触控输入，不派发伪键盘事件作为核心实现。按住状态与单次触发区分，忽略不应重复触发的 key repeat；移动对角归一化。游戏获得焦点且在操作时才拦截对应默认行为，输入框不抢按键。开始和重新获得焦点无需鼠标。

## 电脑／手机操作模式切换

- 所有已有及后续新建的 3D 游戏都必须提供“自动识别 / 电脑键鼠 / 手机触屏”三种模式，并在设置中提供可点击的电脑／手机快捷切换；手动模式优先于自动识别，且可恢复自动。
- 三个选项必须显示当前已选中的状态：明显的背景/边框/文字对比，并同步 aria-pressed；不能只写属性却外观相同。
- 模式切换立即生效，不重开本局、不丢失当前进度；同时更新虚拟摇杆、动作按钮、提示、输入映射与布局。切换时释放键盘、触控、鼠标拖动和锁定状态，避免角色继续移动或动作连发。
- 2D 休闲游戏只在键鼠与触屏存在不同布局、虚拟摇杆或动作按钮时强制提供同样的模式切换；只有点击／拖拽等同一套输入即可完成，或明确单平台的游戏，可省略并在版本 overview 记录原因。
- 验收至少覆盖电脑→手机、手机→电脑、自动→手动→自动，实际按钮效果、横竖视口和本局进度保留。桌面模拟只证明操作与布局，不代替真机多指触控和性能验收。

## 视角控件命名

- 连续转动观察方向：完整名称「转动视角」，紧凑按钮用「转视角」，左右独立键用「左转视角／右转视角」，拖动区域提示用「拖动转视角」。
- 切换预设或第一／第三人称：用「切换视角」，需要区分时明确写「切换视角预设」或「切换人称」；可同时显示当前人称。不要把只切换远近、俯视等预设的 C 键叫「转视角」。
- 同一动作的按钮、键位设置、操作说明和无障碍标签用词一致，不单用含糊的「镜头」；这是玩家界面用词约定，不要求改相机代码标识或拍摄术语。既有游戏在相关改动时对齐，不因改技能批量修改其他游戏。

## 全 3D 视角

- 按玩法选择 3～5 个镜头预设，各类型的默认与可选预设见 [标准游戏选项](game-options.md) 的视角表：必须有「正视」（主角身后看向前进方向），有主角的再在正视之后接「第一人称」；横向闯关默认侧视，可切斜视、正视、第一人称；坦克 / 俯视射击默认斜俯视，可切俯视、正视、第一人称。预设即时切换；菜单的「视角」项与 C 键同步；不得靠鼠标才能发现目标或完成瞄准。正视与第一人称下 W / 摇杆上就是前进。
- **C 循环切换预设**：按下沿触发一次，按住不连续轮转，切换时把 Q/E 转过的角度回正。不设上下俯仰按键（之前的 R/F 俯仰按钮已移除），高度差异由预设提供。
- **所有游戏都有 Q/E 无极旋转**：按住左右连续转动，可转满 360°，角速度乘实际 dt；Q/E 同按抵消，松开、暂停、失焦后停止。移动与射击按视角表最后一列的方式随相机映射（自由 / 吸附四方向 / 单轴），细则见标准游戏选项。不要保留未实现的控件。
- 手机端转视角（用户 2026-10-05 更新）：不设左转/右转虚拟键，在画面任意处按住拖动实现无极转视角——排除摇杆区与动作按钮（`closest` 判断命中即忽略），单指跟踪，横向累积 dx 交游戏循环按灵敏度旋转；暂停、切视角预设、失焦与输入清空时丢弃未消费的拖动量。优先沿用已有多点 Pointer Events；左移动（摇杆）、拖动转视角和动作支持并行多点触控，视角操作不能覆盖 J/K/L 等动作区。
- 需要持续瞄准与射击的玩法优先加入合适的目标辅助、软锁定或清楚的准星，减轻键盘旋转与动作的协调负担；不能把“自动命中一切”当默认设计。

## 角色视线与平滑转向

用户 2026-10-06 最新要求：统一所有 3D 游戏、所有预设的旋转方式。拖动和 Q/E 必须联动主角身体、头部或载具炮塔，镜头跟随该角色视线；世界物体不旋转，不允许只让相机独立绕场景转而主角部位完全不动。第三人称可保持各预设的机位偏移，但转向与角色联动；第一人称位于眼睛/驾驶舱。自动攻击玩法可保留身体攻击朝向、由头部随视线转动。以后新开发或修改均须实现电脑鼠标和手机触屏空白处拖动，不只写提示。此条替代早先允许第三人称仅环绕、身体不联动的说明。

- 拖动增量交游戏循环按逻辑屏宽校准，第一人称使用较低灵敏度、按 dt 限制角速度并平滑消费，不能在 pointermove 里直接跳转几乎半圈；连续拖动仍可转满 360°，不限制总观察范围。积压量有界，暂停、失焦、切预设、操作模式或尺寸变化时清空，避免恢复后自行转头。约 60°/秒可作驾驶舱初始调校参考，最终以实际手感验证，不强制其他玩法固定此值。
- 视线、移动方向分别计算；站立拖动联动身体/头部/炮塔，普通视角行走转向移动方向，不让旧视线目标持续覆盖行走；第一人称保持慢速视线。第一人称横移／倒退不能让镜头随离散 8 向输入突然转 45°／90°／180°；若采用车头 + 视角偏移，补偿的是模型每帧实际转角，不能先补偿目标角度再让模型缓慢追上。身体需要转向时按最短角平滑转动。
- 移动映射按实际水平视线计算；按住摇杆／方向键同时转头仍可更新移动方向，不能保留已经失效的方向锁定。第一人称的跟随射击与投掷按视线发射；明确选择“原作朝上”等固定方向规则时保留该选项并写清。
- 验收包含横移、倒退、快速反向、快速划屏、跨 ±π、连续多圈、移动 + 转头 + 动作并行，以及暂停／失焦／模式／尺寸／预设切换后无残留输入。比较连续帧的实际相机前向量与角速度，不能只看 yaw 变化；手机结果注明触控模拟或真机。

## 暂停与按钮外观

- 所有暂停都暂停 BGM：手动、锁屏、页面隐藏、失焦和退出全屏导致的暂停一致。冻结音频时间，继续本局才从暂停位置续播；音效也随音频上下文暂停，暂停菜单的点击/音量调整不应恢复音乐。可用 AudioContext.suspend/resume，原版音源和合成音同样遵守。
- 按钮去除装饰性小圆圈、白色圆点高光或叠在字母旁的圆圈，不删除圆形按钮主体、摇杆或实际状态控件。保持文字、大小和按下/焦点反馈。
- 验收测量暂停前后音频 currentTime、恢复播放与解锁不误恢复，并注明锁屏以 visibilitychange 模拟或真机实测。

## 手机触屏与横屏布局

- 左下虚拟摇杆，右下动作键方阵；仅显示当前游戏实际存在的动作，字母与简短功能标签同时可辨。
- 右下动作键统一为小霸王 / 街机式 2×2 方阵（用户 2026-10-05 确认，替代此前的环形布局）：四键等大圆键、横平竖直对齐，下排 J（A）左、K（B）右，上排 U（C）左、I（D）右，与键盘位置一致；手机横屏参考尺寸约 76px、间距 12px，贴右下安全区。超过 4 个动作时往右加一列（O 在上、L 在下），不往上加第三排（横屏时右拇指够不着）。不足 4 个动作时只保留实际存在的键，位置不变（如只有两个动作就只有下排 J K）。
- 右上视角、暂停/菜单、全屏按赤色要塞参考排成一行，贴游戏逻辑右上角，距上/右边约10 CSS px并加安全区；横竖旋转、缩放、紧凑样式不能留下旧的内缩预留或把按钮拉到中间。HUD与敌军计数放下方或左侧，不能挡按钮。按钮文字保持完整单行（例如“切换视角”不拆成两段），按文字给足宽度、nowrap与最小44 CSS px触控高度；原创多动作可保留功能布局，右上通用操作同样清楚可达。全屏按实际浏览器能力检测，不因手机分类隐藏，拒绝时保留可玩回退。
- 切换视角（C）不放进动作方阵：手机放在右上角暂停按钮旁（如「C 侧视」「Ⅱ 暂停」）；右上角按钮在触屏下按下即触发（pointerdown），不要只靠 click——快速拖动转视角后的第一下点击会被浏览器当作「停止惯性滑动」吞掉。
- 触屏模式下任何 UI（菜单键位说明、toast、暂停面板、切视角提示）不得出现键盘专属提示（Q/E、Enter、Esc 等）；键盘提示只在桌面键鼠布局出现。切视角等操作的 toast 提示按当前输入模式区分文案（如第一人称：键盘「Q/E 转头」、触屏「按住画面拖动」）。
- 横屏使用整个可用视口，不强制所有手机裁成 16:9；HUD、摇杆和按键按宽高比与安全区适配，核心游戏内容不可被刘海、圆角、系统手势区或按键遮住。
- 用 Pointer Events 跟踪各 pointerId、捕获与释放；pointercancel、失焦、切后台、暂停和退出全屏均清空输入，避免角色持续移动或连发。操作区设置恰当 touch-action，支持边移动边按住动作和转镜头。
- 虚拟按键触控目标至少约 44 CSS px，保留间距与按下反馈；触屏设备默认显示，并提供手动显示切换以支持混合设备。桌面默认隐藏触屏覆盖层、显示键盘说明。
- 手机打开时菜单正常显示；进入选人画面（或无选人画面的游戏在开始后）若视口竖屏，交换游戏容器逻辑宽高并旋转90度，取消横屏阻断提示（用户 2026-10-05 更新：选人画面即旋转，不等开局）。触控点必须通过逆变换映射到游戏逻辑坐标，摇杆、动作键、视角键和多点触控分别实测。横竖切换和窗口尺寸变化时更新相机、控件布局与安全区，并清除按住状态；菜单提供明确的“返回游戏列表”入口，不能盲用 history.back 跳出网站。

## 拖动方向统一规则

用户 2026-10-05 确认以虫潮围城为基准：逻辑横屏中向右拖，观察方向向屏幕右侧转；向左拖反之。固定远处参照物随右转向画面左侧移动。侧视、斜视、俯视、角色身后及第一人称都采用这一语义，不在普通视角使用拖场景、第一人称使用转头的两套相反方向。Q 左转、E 右转与拖动一致。

- 先把物理指针坐标逆变换为逻辑游戏坐标，再计算横向增量。容器顺时针旋转 90° 时，物理向下拖对应逻辑向右拖，不能直接用 clientX 判断。
- 不强制所有游戏的 yaw 使用同一符号。相机前向量为 `(-sin(yaw),0,-cos(yaw))` 时向右看要减 yaw；为 `(sin(yaw),0,cos(yaw))` 时同样减 yaw；赤色要塞驾驶舱的 `(sin(yaw),0,-cos(yaw))` 则加 yaw。以实际相机前向量及右向量验证，包含第一人称阵亡后回退的镜头。
- 每个预设分别验证右拖、左拖、Q/E 和 C 切换后再次拖动；覆盖桌面鼠标、手机横屏及竖屏旋转后的触控。验收比较相机水平前向量的新方向在原右向量上的投影（右转为正、左转为负），并查看连续画面；不能只检查 yaw 发生变化或正负号。同时保留暂停、模式切换、失焦时释放拖动和摇杆／动作区不触发视角的检查。模拟结果注明为浏览器触控模拟。

## 战斗信息与画面安全区

- 默认精简贴边：生命/耐久、当前武器与必要资源、即时目标常驻；最高分、累计统计、完整操作说明进入暂停或玩家主动打开的详情。Boss 阶段可自动收起已不相关的任务信息，结束后恢复。低血量、冷却、弹药与失败条件不能为了清爽而消失。
- 战斗信息可用小块半透明底板、清楚的文字和描边。透明只作用于底板，不降低整块 HUD 的 opacity，不让血条与文字一起变淡；浅色/深色场景都须可读，不依赖大面积模糊或完全透明。暂停菜单保留高对比实色底板。具体透明度由实机画面决定，不统一套数值。
- 顶部中央优先留给前进方向与远处目标。Boss 状态条可移至底部中央或其他空闲边缘，避开摇杆、动作键与提示；复杂原创游戏按玩法分层，不照搬赤色要塞的所有位置。临时横幅与说明不得持续挡住攻击预警、目标或操作区。
- 镜头构图按实际可用画面安排，检查 Boss 模型全身、头部/弱点、主角和主要弹道，不能只判断地面坐标点在屏幕内。默认战斗视角优先通过精简信息、移位与留白看清目标，保留原有场地与模型比例；不为HUD避让擅自自动拉远。用户要求固定机位时沿用原预设距离；确需改观察中心或距离时先展示实际效果，确认不会让角色、目标变小或改变玩法感受。
- 不默认缩小游戏容器并设置一圈信息栏，尤其手机横屏；电脑宽屏的外围信息布局可按需作为选项。镜头避让不得顺带改变射程、敌人激活/开火或胜负判定；游戏将渲染和战斗判定耦合时，先确认行为影响再调整。
- 验收覆盖桌面、手机横屏/更窄横屏、竖屏旋转、所有预设与代表性转角、Boss 战开始/进行/结束、低血量和操作模式切换。保存含 DOM HUD 的截图，以实际模型投影或画面核对遮挡；只有 Canvas 的截图不能证明 HUD 不挡。自由第一人称保留玩家转头，区分默认机位可见与近距离需要抬头。

## 沉浸显示与浏览器限制

- 游戏页面初始化就填满可用视口，隐藏该游戏页面的本站 header/nav/footer、面包屑和其他外围布局；不要全站修改共享样式影响工具页。嵌入 iframe 时检查外层容器限制与全屏授权。
- Toy 宿主页把游戏放在 iframe 里，B 站 App 中可能以 0×0 尺寸启动、拿到真实尺寸后不发 resize（2026-10-03 虫潮实测：画面卡在右下角、不旋转、按钮在屏幕外）。缩放计算要防 0/NaN（读不到时回退 documentElement、visualViewport、屏幕尺寸），并定时或用 ResizeObserver 检查尺寸变化后自己重排，同时重算画布像素比；用“启动时尺寸为 0 且不发 resize”的模拟纳入手机验收。
- 游戏容器包含画面、HUD 与虚拟控制层，对整个容器请求全屏，不能只全屏 Canvas 导致按键消失。使用动态视口高度及安全区留白，处理 resize、方向变化和 fullscreenchange，不让页面产生意外滚动条。
- 开始按钮或 Enter 只开始游戏并解锁音频，不请求全屏。仅通过独立全屏按钮请求包含画面与控件的全屏；旋转布局可对文档根节点全屏，避免容器全屏样式破坏变换。成功后可尝试横屏锁定，拒绝或不支持时继续使用可玩的旋转布局。
- 本站页头可以主动隐藏；浏览器地址栏、系统状态栏是否隐藏取决于浏览器全屏能力。不能承诺页面载入就自动真全屏，也不能把 CSS 铺满视口宣称为 Fullscreen API 成功。失败仍能横屏玩，并简短提示可点全屏或旋转设备。
- 保留暂停、退出全屏和返回游戏中心入口，支持触屏及键盘。不要锁死浏览器返回、系统手势或 Esc。

2026-09-28 核对的技术依据：[requestFullscreen 的用户操作与权限要求](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen)、[横屏锁定的支持与限制](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock)。实现时按实际目标浏览器检测，不按设备名称猜能力。

## 镜头与移动的对应验收

相机相对移动必须把屏幕输入通过水平相机右向量、前向量映射到世界XZ平面，并归一化对角线；不能只旋转画面而保持原世界轴键位。移动朝向与射击使用同一世界方向。验证每个可选视角下的WASD、摇杆、跳跃与射击；视角过渡采用明确且一致的映射方式，避免过渡时方向突然反转。Q/E 转过 90°、180° 时分别复测移动与射击方向。
