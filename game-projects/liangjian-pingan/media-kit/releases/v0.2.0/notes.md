# v0.2.0 开发记录（2026-10-13，本地重做版·枪战类操作规范）

## 本次目标

用户试玩 v0.1.0 后的原话：「以下问题的结果要同时修改这个游戏和 game-maker 技能：枪火集结这样的游戏，比如亮剑，到底要不要有跳跃？适合完全做成 cs 这样的第一人称自己瞄准自己射击，自己换子弹，还是一部分自动？要不要操作全屏操控腾讯的和平精英手游，当然 pc 模式也要参考 pc 模式。现在左右旋转视角用的 q 和 r，要不要加入上下旋转镜头的按钮……你先给我几个合理的建议，我自己选择。」

我给了几套方案，用户两轮选择后的结论：

| 项 | 用户选的 |
| --- | --- |
| 跳跃 | 加自由跳跃（关卡要有能跳上去、跳过去的东西） |
| 射击 | 固定「辅助」一档：手动瞄准带吸附、手动开火、换弹自动 + 手动，不做档位切换 |
| 布局 | 精简和平精英布局；电脑鼠标瞄准（默认按住拖动，鼠标锁定可选）；JKUI 纯键盘必须能打完 |
| 视角 | 只留两个：第三人称（默认）+ 第一人称 |
| 转视角按键 | 左右保持 Q/E；上下用 Y/H，并定为所有 3D 游戏的统一规则（老游戏改到时再加） |
| 范围 | 只改这个重做版和技能；原版《枪火集结》、虫潮战地 / 抗战不动；仍只在本地，不推送不发布 |

观众能理解的问题：**同一关，从“自动锁定的俯视街机”改成“自己瞄准的越肩射击”，要动多少东西？**

范围属于第三类（在现有游戏上改操作与玩法），关卡仍是一关五个阶段。

## 改了什么（相对 v0.1.0）

- **视角**四个改两个：越肩第三人称（默认）、第一人称。旧存档的视角只换算一次（旧的斜俯视 / 战术俯视 / 正视 → 第三人称，旧的第一人称 → 第一人称）。
- **射击**从“按住自动锁定”改成自己瞄准：准星射线求落点，子弹从枪口打向落点；准星附近有子弹吸附（触屏、按键约 4.2°，鼠标约 2.2°，从敌人身体边缘算，要有视线），触屏和按键另有准星减速与开火牵引；爆头 ×2；弹匣 20 / 40，打空自动换弹、R 手动换弹，去掉了“停火 1.6 秒自动补满”；新增开镜。
- **跳跃**：约 1.3 米、空中可控、无二段跳。碰撞改成按高度判断，可以站在箱子、土坎、棚顶、阵地侧墙上。关卡里加了让跳跃有用的东西：铁丝网（走不过、跳得过）、两处土坎旁的弹药箱台阶、街垒前的箱子、十字街口的箱子台阶和矮棚顶、决战场地两侧的箱子；山本的贴地突进可以跳起来躲。
- **按键**：J 开火、K 跳、U 亮剑、I 骑兵连、L 手榴弹、O 开镜、R 换弹、F 上炮 / 离炮，Q/E 左右、Y/H 上下；鼠标左键开火、右键开镜、空格跳、G 手榴弹、V / X 技能、Shift 开镜。上炮从 J 改成 F，免得和开火抢键。
- **手机布局**：左半屏浮动摇杆，右半屏滑动瞄准，大开火键按住可以拖着瞄，另有跳、开镜、换弹、手榴弹、亮剑、骑兵连，靠近炮位才出现“操炮”；可开左手开火键。
- **设置**新增瞄准灵敏度、鼠标瞄准（按住拖动 / 鼠标锁定）、左手开火键；主菜单宽屏改四列。
- **数值**按手动瞄准重调：敌人血量下调（步兵 2、机枪手 6、军官 5、特工 7、山本 280），巷战两组各少一人，敌人开火间隔拉长。敌人和战友会绕开新加的障碍。
- **街垒与敌人射界**（录像暴露问题后改的，见“真实经过”第 10 条）：街垒从 1.6 米降到胸口高，可以隔着沙袋对射；步兵和特工被掩体挡住射界时不再原地开枪，会斜着往前绕出来。
- 没动的：五个阶段的流程、梗与喊话、命数与耐久、三种操作模式、竖屏旋转、暂停与声音、画风。

## 真实经过

1. **先问清楚再动手**：这次不是我自己定方案。把跳跃、瞄准方式、布局、上下看的按键各列了几种做法和利弊，用户逐项选。上下看的键我列了 Y/H、R/F、方向键、不加四种，推荐 Y/H（R 留给换弹、F 留给互动），用户选了 Y/H，并追问左右要不要也换，最后定为 Q/E 不变。
2. **头挡住了准星**：越肩视角第一版，平视时李云龙的后脑勺正好压在准星上，开镜更是贴脸。把镜头支点抬到 1.95 米、肩部偏移加到 0.7（开镜 0.95），开镜距离定在 3.1 米才看得清前面。
3. **跳不上箱子**：第一版跳跃滞空太长、箱子又小，助跑一跳就飞过去了。箱子加大到 1.9 米见方，滞空压到约 0.63 秒，空中速度打八五折，落点判定给边缘留 0.3 米余量，才稳定落得上去。验收脚本原先写的是“跳完看停在哪”，也改成逐帧看有没有落在箱顶。
4. **离炮又上炮**：F 改成上炮 / 离炮共用之后，离开的那一下按键没清掉，下一帧又坐回去了。离炮后清掉这次互动输入。
5. **敌人被新土坎卡住**：加了能站上去的土坎后，第一阶段有敌人顶在土坎后面出不来，自动通关脚本一直等不到人。敌人原来只会直线走向目标，这次加了贴着障碍侧绕和卡住检测。
6. **骑兵从镜头里穿过去**：俯视时没问题的冲锋线路，到了越肩视角正好经过镜头位置，战马的肚子糊一脸。把线路让开中间，分到两侧。
7. **机枪阵地的吸附角**：验收里“鼠标偏 3° 应该打不中”一直失败，查下来不是 bug——吸附角是从敌人身体边缘算的，3° 落在身体半径加吸附角以内。测试改成偏 4.5°。
8. **脚本自己绕不过去**：改成手动瞄准后，原来的按键脚本不能用了，重写成自己转准星、自己按开火的版本。它一度站在 6 米宽的土坎后面对着土坎开火，不是游戏卡死，是脚本不会绕；加了“打不到就横移一秒、三次换边”。另外实时跑每次结果不同，改成确定性步进后三档耐久的结果才稳定可比。
9. **手机上两处挤**：844×346 的结算面板因为多了爆头、跳跃两项统计要滚动才看得全，统计改三列；“操炮”键一开始被提示条压住，挪了位置。
10. **录像录出一场十分钟的对峙**：所有验收都过了，最后实时录整局录像，结果 12 分钟超时没打完。抽帧一看，从第 130 秒起李云龙就站在第四阶段的街垒前，三个鬼子站在沙袋后面，谁也打不到谁（原片在 `../v0.2.0-dev01/captures/`）。起初以为只是脚本不会绕路，用确定性脚本复现才发现真人也会碰到：看得见守军露出来的头，35 发子弹全打在沙袋上，离 12 米也一样；守军的子弹同样被自己面前的沙袋挡住。原因有两层——街垒沙袋的碰撞高度 1.6 米，比双方枪口都高；敌人判断射界时又忽略 1.7 米以下的掩体，以为自己打得到，就站着对沙袋开枪。改法：街垒降到胸口高（四层沙袋、碰撞 1.1 米，主角能直接跳上去），步兵和特工的射界改按子弹实际高度算、矮掩体也算进去，没有射界时斜着往前绕出掩体。改完后站在街垒前瞄头一枪击倒，守军十秒内也能越过沙袋打中主角；这三条写进了 `views.cjs`。之前三档确定性通关都没撞上（推测是那几次的走位没有停在街垒正面，没有再去验证），实时录像每次走位不同，才把它撞出来。

## 验证与测量（最终构建 local-865548dbd0f5）

- 视角、射击、跳跃、街垒 73/73（另有 1 条只记录“本次环境是否允许鼠标锁定”），双端布局 112/112，选项与规则 44/44，冒烟无报错。都是在修完街垒之后的最终构建上重跑的。
- 手动瞄准脚本三档耐久各通关一遍、无脚本报错：标准 268.1 秒（阵亡 6 次，第四阶段 140.8 秒）；宽松 204.2 秒（阵亡 2 次，第四阶段 75.8 秒）；一发 185.4 秒（阵亡 13 次，第四阶段 54 秒）。脚本瞄的是上胸、不用掩体，爆头数偏高；这些数字只说明流程不软锁，不代表真人难度。修街垒之前同一脚本的结果是标准 172.7 秒、宽松 202.2 秒、一发 413.8 秒，两组不能直接比（脚本的瞄准高度也改了）。
- 帧时间（本机 RTX 4060 Ti，Edge 无头，实时运行）：1920×1080 与 1280×720 高画质约 163～166 帧；约 2.2 万帧桌面采样里有 3 帧超过 50 毫秒，最长一帧 53 毫秒（第 4 阶段，1920×1080，第三人称）；手机视口模拟（844×390、像素比 3、流畅画质）超过 50 毫秒的帧 0 帧。修街垒之前那次测量出现过一帧 146 毫秒（第二阶段），原因没查到，这次没有再出现。这不是手机性能。
- 全屏按钮对整页生效；以 0×0 的 iframe 启动、之后才给尺寸，能自己按 844×390 重排。
- 鼠标锁定在无头 Edge 里能进入、锁定后移动鼠标能转视角、退出即暂停。“被拒绝时回退到按住拖动”这条分支代码里有，但这次的环境允许锁定，没有走到。
- 三个新设置里，左手开火键和鼠标瞄准的实际效果测过；瞄准灵敏度只测了能切换和保存，三档手感没有验证。
- 录像 `captures/playthrough-view0-p1.webm`：1280×720、168.2 秒、无音轨，脚本实时操作，打到“平安县城，拿下了！”（游戏内 162 秒，阵亡 2 次）。抽了 9 帧看过，五个阶段和结算都在；没有逐帧看。

## 待办（等用户试玩后的指示）

- 手感类的全部待定：吸附强弱、灵敏度三档的数值、跳跃高度与滞空、敌人血量与人数。
- 既有《枪火集结》、虫潮战地 / 抗战要不要迁到新规范、什么时候迁，由用户点名。
- Y/H 定为统一键位后，虫潮围城与《枪火集结》里 H（医疗 / 直升机降低）、Y（直升机升高）和它冲突：我的建议是把 H 的原功能挪到 N、升高只留 K，这次没有动这两款，改到它们时再向用户确认。
