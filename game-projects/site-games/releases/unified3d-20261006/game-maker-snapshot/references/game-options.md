# 标准游戏选项

用户 2026-10-02 要求：所有适合的游戏都提供命数、耐久、演示模式等选项，视角按游戏类型提供多种。参考实现：赤色要塞 3D v0.2（`D:/project/claude/test/game-projects/jackal-stage1-3d`，`src/main.js` 的设置与菜单、`src/game.js` 的受击与修理包）。

## 选项组与位置

| 选项 | 取值（第一个为默认） | 主菜单 | 暂停菜单 | 本地保存 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 命数 | 无限命 / 经典 N 命 | ✓ | — | ✓ | 只在开局前切换；N 按原作或题材定，常见 3 命 |
| 耐久 | 标准多格 / 经典一发 | ✓ | — | ✓ | 有受伤机制时提供，见下文 |
| 演示模式（无敌） | 关 / 开 | ✓ | ✓ | ✗ | 每次载入都是关；开启有醒目标识，本局不计最高分 |
| 视角（C） | 按类型 3～5 个预设，必含正视；有主角的再加第一人称 | ✓ | ✓ | ✓ | 与 C 键、手机 C 键同步；Q/E 旋转角不保存 |
| 画质 | 自动（按实测帧率）/ 高 / 流畅 | ✓ | ✓ | ✓ | 自动档显示当前实际档位 |
| 音量 | 0～100%，步进 10% | ✓ | ✓ | ✓ | 0 即静音 |
| 触屏按键 | 自动 / 显示 / 隐藏 | ✓ | — | ✓ | 给混合设备手动切换 |
| 帧率显示 | 关 / 开 | ✓ | ✓ | ✓ | 角落小字，不挡 HUD |
| 全屏 | 独立按钮 | ✓ | ✓ | — | 规则见 [横屏与统一操作](controls-and-display.md) |
| 返回游戏列表 | 普通链接 | ✓ | ✓ | — | 结算界面也有 |

暂停菜单另有「继续」「重新开始」「返回主菜单」；结算菜单有「再玩一次」「返回主菜单」「返回游戏列表」。

- 选项按钮显示「名称 ◂ 当前值 ▸」。键盘 ↑↓ 选择、←→ 调整，Enter 也能切换；触屏点一下切到下一个值；触控高度不低于约 40 CSS px。紧凑横屏可排成两列，开始按钮占满一行。
- 设置写入 localStorage 的独立命名空间，读写都包 try/catch，读不到就用默认值。测试用 URL 参数可以临时覆盖画质等设置，但不写回。
- 命数和耐久属于本局规则，开局后不改；要换就回主菜单。结算注明本局的命数和耐久模式（标准耐久再写受击次数、补给数）；最高分可以共用，但演示局不计。
- 题材不适合时省略或替换：没有伤害、没有失败的解谜、经营、休闲游戏不设命数和耐久，可换成贴合题材的辅助项（提示、撤销、计时宽松 / 标准等）；不为凑齐表格去加系统。省略或替换的原因写进 media-kit 的 overview。
- 菜单里只放已经实现、和实际规则一致的选项。

## 命数

- 默认无限命：从最近的安全检查点复活，复活后约 2～3 秒闪烁无敌；附近敌人推迟开火、清掉近身敌弹，避免复活点被压制。阵亡惩罚（武器降级、散落物品等）按题材保留。
- 经典 N 命：命用完进入失败结算；可以照原作按分数奖命。HUD 显示 ∞ 或 ×N。
- 无限命下核心失败条件仍然有效，例如基地被毁、时间耗尽。

## 耐久

- 默认「标准」：多格护甲或血量，常用 3 格。被击中扣 1 格（规则先保持简单，强敌加倍伤害要实测后再定），之后约 1～1.5 秒闪烁无敌，免得连发或三连炮一下打空。
- 受击反馈要清楚：角色闪白或闪红、屏幕四周短暂红边、HUD 格子减少、受击音效、轻微镜头震动。只剩 1 格时 HUD 变红闪烁，并有符合题材的持续提示（冒烟、喘息等）。闪白期间不要被无敌闪烁隐藏；红边等效果按游戏时间衰减，不用按真实时间播放的 CSS 动画，这样离线逐帧录制也拍得到。
- 补给来源固定、可预期，并和主线绑定（例如每个营房、宝箱或据点掉一个），不做随机掉率。满血时补给留在原地，之后可以回来拿；检查点和复活时补满。
- 「经典一发」（或贴近原作的耐久值）作为可选项：一击即毁，HUD 只显示 1 格并标注；补给改为加分等非生命奖励，保证两种模式的关卡内容一致。
- 复刻经典作品时，原作的生命规则作为「经典」选项保留，默认用标准耐久降低挫败感；用户另有要求时照办。
- 已有血条的游戏可以把耐久映射为「标准 / 经典一发」或「宽松 / 标准 / 经典」，规则在菜单或说明里一句话讲清。
- 难度对比用同一个 bot 分别跑标准和经典（可加一组不躲子弹的），记录阵亡和受击次数；只能说明压力变化，不能代替真人试玩。

## 演示模式（无敌）

- 默认关闭，主菜单和暂停菜单都能切换。开启后有固定的醒目标识（如右上角「演示模式 · 无敌」）和角色护罩；敌方攻击无效，其余流程照常。本局只要开过就不计最高分，结算写明。
- 演示模式用于展示和录制，功能验收和难度数据不能拿它代替。

## 视角预设（按游戏类型）

用户 2026-10-02 决定：所有游戏都有 Q/E 无极左右旋转，用于多角度观察和为视频拍更好的素材；不设上下俯仰按键，俯仰高度靠 C 预设区分。2026-10-05 更新：Q/E 仅限电脑键盘，手机不设左右转动虚拟键，改为画面按住拖动转视角（实现要点见 controls-and-display）。

**C 预设**：每款 3D 游戏提供 3～5 个都能完整游玩的视角预设，默认选最适合玩法的一个；其中必须有「正视」，有可操控主角的再在正视之后接「第一人称」（见下文「正视与第一人称」）。玩法简单、画面信息少的类型默认 + 一个补充视角 + 正视即可。C 键按下沿循环并把 Q/E 转过的角度回正到该预设的默认朝向；循环顺序把第一人称放在正视后面（如 侧视 → 斜视 → 正视 → 第一人称 → 侧视）；手机提供 C 按钮，主菜单和暂停菜单的「视角」项同步显示当前预设。

| 游戏类型 | 默认 | 其他预设 | 移动随 Q/E 旋转的映射 |
| --- | --- | --- | --- |
| 横向闯关 / 平台跳跃 | 侧视 | 斜视、正视（身后看向前进方向）、第一人称 | 侧视/斜视单轴；正视/第一人称自由 |
| 坦克、俯视射击、俯视驾驶（如坦克大战、赤色要塞） | 斜俯视 | 正俯视、近景斜视、正视（车后追尾）、第一人称（驾驶舱 / 炮塔） | 自由；按格移动的吸附四方向 |
| 纵向卷轴射击 | 后上方斜视 | 正俯视、正视（低角度追尾）、第一人称（座舱） | 自由 |
| 跑酷 / 固定前进方向的追逐 | 正视（后方跟随） | 高位跟随、侧面、第一人称 | 单轴 |
| 第三人称动作 / 冒险 | 正视（后方跟随） | 高位跟随、远景、第一人称 | 自由 |
| 赛车 / 驾驶 | 正视（车后追尾） | 高空、车头低位、第一人称（驾驶舱） | 不变（转向本来就相对车身） |
| 塔防 / 基地防守 / 即时战略 | 斜俯视 | 正俯视、近景、正视（有可操控主角时在其身后，否则从基地看向敌人来向）、第一人称（有主角时） | 自由 |
| 平面益智 / 棋盘 / 消除 / 经营 / 休闲 | 等距斜视 | 正俯视、正视（坐在玩家一侧看向桌面远端）；无主角不设第一人称 | 吸附四方向 |
| 立体解谜（3D 推箱子、积木、魔方等） | 等距斜视 | 正俯视、近景、正视、第一人称（有主角时，如推箱子的工人） | 吸附四方向 |

**Q/E 无极旋转**：按住 Q 左转、E 右转，联动主角身体/头部/炮塔并让镜头在水平方向连续转动，可转满 360° 不设限；角速度约 90°/秒并乘实际 dt，起停可略带缓动，同按抵消，松开、暂停、失焦后停止。Q/E 仅限电脑键盘；手机端改为画面按住拖动转视角（不设左右转动虚拟键），横向拖动累积增量、灵敏度按屏幕宽度校准，不覆盖摇杆与 J/K/L 动作区。旋转角不写入存档，重开一局回到默认预设。

- **移动映射**（上表最后一列）：「自由」按相机水平右向量与前向量映射到世界 XZ 平面；「吸附四方向」先按相机映射，再吸附到最近的世界四方向，保证格子移动不斜走；「单轴」取相机右向量在玩法轴上的投影方向决定 A/D，接近 90° 时保持原方向直到明显越过（滞回），避免左右来回反转。射击、朝向与移动用同一套映射。
- 所有预设与人称切换后保持虫潮的方向：右拖右看、左拖左看，Q 左、E 右。普通环绕与第一人称内部 yaw 定义可以不同；换算与双端验收见 [拖动方向统一规则](controls-and-display.md#拖动方向统一规则)。
- **不需要上下俯仰键**：C 预设已覆盖正俯视、斜视、低角近景等高度，自由俯仰容易钻到地下、看到场景外，也会让手机按键过多（之前已移除 R/F 俯仰按钮）。确有需要再单独提出。
- **全角度不穿帮**：转到任何角度都不能出现缺背面、单面墙、悬空物体、漏光或看到场景外空白；以前只做正面的横版场景要补齐侧面与背面，或用合理的场景边界收住。墙体、建筑挡住主角时把遮挡物淡化或半透明，主角始终可见。
- 预设之间要有实际差别（角度、距离、视野），不做只差几度的凑数视角。每个预设都检查 HUD 遮挡、目标可见范围、敌人进入画面的时机，以及射击方向和画面方向是否一致。
- 「画面上方」类规则（如机枪固定朝上）在所有预设和旋转角度下指向同一世界方向；如果改为随相机变化，要在说明里写清。
- 近景或低角预设可以看得比较近，但不能让某个预设根本无法通关；做不到就不提供该预设。
- 复刻作品默认用最接近原作画面的预设（如 FC 俯视游戏的正俯视、横版游戏的侧视），Q/E 照常提供。
- 录像可以用近景预设拍特写、用 Q/E 慢速转动角色视线展示场景，素材描述里注明当时的视角。

## 正视与第一人称

用户 2026-10-04 要求：所有游戏都要能切到「正视」——镜头在主角身后、看向关卡前进的方向；特别是 3D 复刻经典游戏，正视再切到「第一人称」，代入感最强。参考实现：超级玛丽 3D v2.1.0（`D:/project/toolbasecamp/public/html/game/mario-3d/scene.js` 的 `PRESETS`、`avoid`、`updateCamera`）。

**正视**
- 镜头在主角身后，朝关卡前进方向（横版就是 +x 方向）；W / 摇杆上 = 前进，A / D = 左右，Q/E 照常转。没有主角的游戏从玩家一侧看向桌面或敌人来向。和「纵深」「后上方斜视」这类只差几十度的视角二选一，不并存凑数。
- 机位尽量放在主要遮挡层之间：超级玛丽把镜头放在脚下约 2.6 格，正好从 3 格高的砖块层下面看过去，还能看到头顶要顶的砖。镜头高度跟主角站的地面走、不跟跳跃；跳高时镜头不动、看点抬高（抬头看），主角不能跳出画面。
- 镜头避让：镜头落进方块，或镜头到主角的视线被方块挡住时，先往上抬（限 1～2 格），抬不了再沿视线朝主角头顶后上方拉近，最多拉到离主角约 1.3 格，不越过主角；拉近快、回退慢，避免来回抽动。
- 关卡端墙、天花板挡在镜头和主角之间时做剖面（把墙或天花板整层切掉），避让判定忽略已切掉的部分；贴着镜头 0.5～1.3 格内的物体网点溶解。只靠网点淡化会满屏半透明方块，不能代替避让。
- 阴影范围随镜头朝向往前挪，正视时前方的障碍也有影子。

**第一人称**
- 在 C 循环里紧跟正视之后。镜头放在主角眼睛高度（下蹲、变小随之变矮），不画主角自己（可保留手、武器、车头等能帮助判断位置的部分）；关闭遮挡淡化与剖面；近裁剪面调到约 0.05～0.1，贴墙不穿模；视野 70～80°，给轻微固定俯角，仍不设俯仰键。
- Q/E 转头；移动、射击跟视线方向；站着不动时朝向跟着视线，射击往看的方向打。
- 画面空白处拖动同样转头，镜头改变观察方向而不旋转场景；驾驶舱／角色第一人称使用平滑、限速转头，横移与倒退不让模型转向把视线突然甩走。具体规则和验收见 [角色视线与平滑转向](controls-and-display.md#角色视线与平滑转向)。
- 死亡、过场、Boss 登场等需要看清主角的动画暂时退回正视；标题画面、演示自动平移不用第一人称；退出第一人称后回到正视的机位，不跳变。
- 第一人称看不到脚下，跳坑、踩敌的距离更难判断：保留落点阴影或准星，必要时加轻微的落点辅助，但不降低原作关卡难度；真人试玩手感写进交接。

**验收**
- C 循环顺序与菜单「视角」项同步，名称在手机紧凑菜单里不溢出。
- 正视与第一人称下 WASD / 摇杆方向正确；Q/E 转 90°、180° 后移动与射击方向跟着视线。
- 正视走遍关卡各类地形（砖块层下、台阶顶与台阶后、水管之间、地下关、奖励房间、关卡两端），截图检查镜头没有卡进方块、主角没有被挡、没有满屏半透明块；跳高时主角留在画面内。
- 第一人称下主角模型隐藏、死亡回退正视、标题画面不进第一人称、贴墙不穿模；四种视角各测一次实际帧时间。

## 验收

- 每个选项都测：键盘切换、触屏点击切换、显示值正确、刷新后保留（演示模式除外），以及实际效果：经典命数用完失败、耐久扣格 / 无敌期不扣 / 补给 +1 / 满血不捡 / 检查点与复活补满 / 经典一发一击即毁、演示模式无敌且有标识且不计最高分、每个视角下 WASD / 摇杆 / 射击方向正确、Q/E 键盘与手机画面拖动各转一整圈（含转过 90°、180° 时的移动方向和画面有无穿帮或遮挡主角）、C 回正、画质档位、音量、帧率显示。
- 菜单在桌面、手机横屏、手机竖屏旋转后都完整落在视口内，按钮互不重叠；HUD 的命数与耐久格不压住右上角按钮。
- 媒体交接留一张主菜单选项截图；新增或修改选项时，留切换前后及实际效果的证据。
