# 虫潮 0.38.8：虫潮放大三倍，路上不再刷野怪

来源是玩家在这条 B 站动态下的评论「作者，作者可以怪出多点吗」。用户看过后决定「那就多出怪吧，几倍的出」，并明确「原来地图上的除了母巢里的怪不要有野怪」；讨论过 5 倍，最终选定**全部设备默认 3 倍**，不按设备分档、也不做成设置开关。

## 改了什么

- 主战役每关正式虫潮数量×3：第一章第一关普通 11→33 只，第五章第五关 25→75 只，第十章第五关 33→99 只，第十章第十关首领关小兵 25→76 只。
- 出怪间隔整条曲线除以 √3（第一章第一关普通 2.05s→1.18s），所以一关时长与压力约按 1.7 倍增加，而不是把三倍的虫一次倒进场；三档难度的间隔相对顺序与原有下限不变。
- 同屏上限从写死的 48 只改成按设备放大：电脑单机 144、手机 80、联机 72（联机每约 65ms 把全部单位同步给客人，房主上行是瓶颈）。战役出怪、分裂、首领召唤、测试台与沙盒波次共用这一个上限，达上限时暂停出兵、击杀后继续。
- 准备阶段不再在前中场散布野怪，也不再刷准备阶段小首领：开战前地图上只有虫巢里的母皇与 5 只精英护卫。提前打虫巢、母皇减伤与补给的选择保留；残留在场上的非老巢虫仍会在开战时加入本关进攻，战术预告与 HUD 的措辞由「场上野怪」改为「场上残虫」。本段替代 v0.20.0「现有野怪另列」的准备阶段布怪描述。
- 金币按 √倍数 回落：虫潮出兵表里的小兵与精英单只掉落到约 58%（第一章普通小兵 12→7 金币），一关总收益约 1.7 倍。首领、小首领、通关奖励、副本与自由测试的单只掉落不变。基地耐久、城门耐久、虫族血量与伤害都没有下调，即这一版没有靠降难度来抵消怪多。

## 共用模块的处理

`campaign-difficulty.js` 原本是虫潮围城与枪火集结的共用模块。3 倍虫潮只对虫潮成立（枪火集结是抗战战役的人海，玩家没有提这个需求），所以把它从 `shared-modules.json` 的 `shared` 移到 `perGame`，两款各自保留一份并在清单里写明分叉原因；`shared/` 目录仍留无倍数基线供 `tactical-waves.js` 引用。函数签名未变（`tacticalWavePlan` 仍按五个参数调用），所以 `tactical-waves.js` 继续共用、逐字节一致。漂移检查 `node game-projects/site-games/shared/sync-shared.mjs` 通过（23 个共用模块一致，无未归类模块）。

## 验证

- `verify-swarm-scale.cjs` 5 项：准备阶段只剩母巢（母皇 1 + 护卫 5，场上野怪 0，第五章第五关同样为 0）、HUD 与预告数量等于开战虫潮、第一章普通 11→33、虫潮掉落 12→7 且间隔 2.05/√3、后期间隔有下限且三档顺序不变、同屏上限真正拦住出怪、手机上限 80。全通过。
- `verify-campaign-difficulty.cjs` 桌面／横屏／竖屏三视口全通过，800 组曲线无「金币滚雪球」等问题（最高倍率 1.133 < 1.15），无页面报错。这个脚本自 0.37.0 菜单改版后就失效，本次顺带补回「存档与恢复」「游戏设置」两个入口的点击路径。
- `verify-playthrough-v09.cjs` 实时键盘机器人（不按伤害/击杀钩子，真实打完整关）五档全胜、基地耐久全程满：68/86/93/96/101 秒；0.38.7 同夹具基线 43/48/58/71/68 秒，时长比约 1.5～1.7 倍，与 √3 的设计一致。
- 视觉抽查（1280×720，第五章第五关）：准备阶段战场与 minimap 上没有野怪，HUD 显示「本关虫潮 75 只」；开战后三路同时来虫，场上 43 只、待增援 21 只时基地仍 2000/2000。
- 性能：电脑端 150 只同屏帧时基本平坦；844×390 + 4 倍 CPU 降频模拟下 96 只约 55 帧、120 只约 49 帧、150 只约 43 帧，据此把手机上限放在 80。**未做真机验收**，手机帧数与触控手感以真机为准。
- 未测：联机多人同屏的实际带宽与延迟（只按同步机制收紧了上限）、音效与语音、玩家主观难度感受。
