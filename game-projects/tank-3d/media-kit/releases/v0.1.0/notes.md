# v0.1.0 开发笔记（真实经历）

## 本次目标
用户指令：「使用 web-game-maker 技能制作网页游戏：FC 坦克大战第一关 3D 版」。目标是把第一关的完整一局（开场 → 守家打坦克 → 吃道具 → 20 辆全灭或老鹰被毁 → 结算 → 重玩）做成电脑键盘与手机横屏都能玩的 Three.js 网页 demo，并按站内规范接入游戏中心。

## 核心变化（给视频用的「反差」）
- 原作是一张平面俯视图；这里墙有了高度、打碎会飞砖，镜头可以从战场俯瞰一路压低到坦克屁股后面（R 键），同一张经典地图变成了能「钻进去」的迷宫。
- 开场做了一个只有 3D 才有的镜头：闸门合上显示 STAGE 1，打开后镜头贴着老鹰掠起，再拉到整张战场。

## 技术路线
- 沿用 mario-3d / contra-3d 已验证的结构：`world.js` 纯逻辑（不引用 THREE，可在 Node 跑）、`scene.js` 渲染、`main.js` 输入与流程、`audio.js` 振荡器音效；Three.js 0.170.0 走仓库 vendor 同源。
- 地图用 26×26 字符串写成，1 格 = 原作 8px；坦克占 2×2 格，转弯自动对齐到整格，所以 2 格宽的通道能顺畅钻过去。
- 砖墙/钢墙各一个 InstancedMesh，被打掉的格子缩成 0；整局只有约 22 个 draw call、8.5k 三角形。
- 先写逻辑与 Node 断言，再写画面：15 项逻辑检查（地图、贴墙、转弯对齐、砖块破坏宽度、钢墙、敌军名单与同屏上限、道具 6 种、护盾、老鹰、命数、通关、4 分钟随机长跑不越界不穿墙）在写渲染前就全部通过。

## 真实问题与处理
1. **事件字段被覆盖（代码自查发现）**：`emit(w, 'pickup', { type: pu.type })` 把事件自己的 `type` 覆盖成了道具名，导致「拾取」和「道具出现」事件会被当成 'star' 之类的未知事件，提示和音效都不会触发。第一次进浏览器之前发现，改为 `kind` 字段。没有运行时录像。
2. **自动测试机器人老打自己的老鹰**：写了一个「对齐就开火」的平衡探针机器人，12 个种子里输掉的局大多是它自己把炮弹打进老鹰围墙。给失败原因加上「是谁打掉的」，结果这成了一个新设计：被自己打掉时结算标题是「你打中了自己的老鹰……」，并有专门的提示。机器人改成不朝围墙开火后胜率 6/12，敌军 AI 同时调低了直奔老鹰的比例和开火频率。
3. **老鹰像只鸭子**：第一版老鹰（圆身体 + 小翅膀）在开场特写里看起来像麻雀/鸭子（assets/dev-stages/02-eagle-v1-before.jpg）。改成白头、钩状黄喙、三层展开的翅膀和白尾（03-eagle-v2-after.jpg）。
4. **闸门把开场镜头挡住了**：第一版闸门动画 1.5 秒，正好和镜头掠过同时发生，最精彩的 3D 镜头被灰色闸门盖住。改为闸门先合上再打开（1.25 秒），镜头在闸门打开后才开始掠起。
5. **GAME OVER 大字压在结算面板后面**：失败面板弹出时升起的 GAME OVER 字样还在，从面板边缘漏出红色字母（assets/dev-stages/04-defeat-panel-overlap-before.jpg）。面板出现时隐藏大字。
6. **手机视角键盖住战场**：844×390 横屏下 Q/E/R/F/C 一排按钮压在战场右下角（05-mobile-camera-pad-overlap-before.jpg）。改成开炮键左侧的 2 列小网格，落在战场外的草地上，按键仍保持 44px 触控尺寸。
7. **旋转回横屏偶尔不恢复**：虚拟时钟测试里，手机从竖屏转回横屏后「请横屏」遮罩没有消失（resize 事件与尺寸更新先后不稳定）。主循环里每 20 帧补查一次方向和画布尺寸，同时监听 orientationchange。
8. **长时间采集被容器重启打断**：第一次离线逐帧采集跑到第 553 帧时云端环境重启，进程全部丢失。把采集改成可续跑：玩法是确定性的（固定种子、固定步长、脚本机器人），重启后先无截图回放到断点再继续截帧；顺便记录每个音效调用的时间，事后用离线音频上下文渲染出同步的游戏音轨。

## 取舍
- 只做第一关原有的内容：砖、钢、老鹰、普通与快速坦克；没有加水、树林、冰面或装甲坦克。
- 按住 J 可以连发（原作要连按），手机上更友好。
- 敌军「携带道具」的第 4/11/18 辆规则、手雷不计分、铁锹到期砖墙完整重建，都按原作习惯做。
- WASD 相对镜头方向：镜头转 90° 后 W 仍是「屏幕上方」，这样压低视角时依然好开。
